# 复盘文档可视化规范

每次复盘文档必须包含 3 个 html5-block。全部用 HTML 单文件实现，通过 lark-doc 的 html5-block 写入（`<html5-block data-ref="html5_N">` + reference-map）。要求：静态可读、核心结论不依赖交互、自适应 820px、单文件 ≤500KB、禁止 emoji、禁止彩虹色。

## 色板（三选一，全程统一）

推荐藏青（决策/复盘类）：
- 主色 `#1A2B4A`，辅助层级 `#758092` / `#BABFC9` / `#DDE0E4`
- 正文 `#1F2329`，说明 `#646A73`，边线 `#DEE3E8`
- 浅底分组 `#F4F6FA` / `#FBFBFC`
- 主体文字 ≥16px，辅助 ≥14px

## Block 1：一图看懂 · 总评

**用途**：一页回答"整体表现如何、强在哪、弱在哪、怎么办"。

结构：
1. **面试性质条**：时间、时长、轮次性质（集中面/业务面）、依据材料（面试记录 + 简历版本）
2. **核心判断卡**（左侧深色边线）：一句总评 + 一句展开（优势 / 短板）
3. **六维评分条**：6 行（维度名 + 进度条 + 分值 x/5）；进度条宽度 = 分值/5×100%，主色填充、浅灰底
4. **正负信号双栏**：左"已建立的正向信号"（主色上边线）、右"主要失分点"（灰上边线）
5. **结论条**：是否通过不做推断，注明证据边界

## Block 2：流程全景 · timeline

**用途**：逐环节复盘，一页看清考察意图、现场应对、评分与信号。

结构：
- 顶部：总时长、环节数、信号图例（亮点/平稳/风险）
- 纵向时间轴（左侧细线 + 节点圆点），每环节一张卡片：
  - 头部：时间段 + 问题名 + 信号标签（亮点=主色底、平稳=灰、风险=深灰）+ 评分摘要
  - 两栏：考察意图 / 我的应对
  - 通栏：关键点评（亮点或失分点，一句话点透）
  - 底部：五维评分行（准确性｜完整性｜逻辑性｜表达力｜岗位匹配）

环节数量 5-10 个时用此布局；超过 10 个按环节类型分组或只保留关键环节。

## Block 3：案例题答题对比

**用途**：开放题/压力题"我的回答 vs 推荐框架"并排对比。

结构：
- 顶部一句总评：两道题的核心差距（如"先讲业务对齐与优先级，再讲工具与流程"）
- 每题一个区块：
  - 题目标题 + 面试官原题简述 + 考察意图
  - 左右双栏：左"我的回答"（灰上边线）、右"推荐框架"（主色上边线），各用有序列表 3-4 步
  - 底部"关键差异/为什么失分"条（浅底 + 左侧主色边线）
- 无开放题时可省略此 block，改为"关键问题回答对比"

## 制作要点
- 每张图只回答一个问题，不拼接多个独立议题
- 评分条、信号标签必须有图例或文字说明
- 数据（评分、指标）必须与正文一致；正文不逐项复述图内内容，只给结论
- 相邻两个 html5-block 之间必须有段落文字过渡
