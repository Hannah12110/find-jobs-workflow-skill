# Interview Review（面试复盘）

基于面试记录 + 简历，输出结构化飞书复盘文档。核心方法论：区分"现场说了什么 / 简历可证事实 / 复盘建议"三层，逐题复盘必须给出可直接背诵的优化版回答。

## 执行流程

### 1. 盘点输入
- 面试记录：飞书 doc/wiki 链接、文本逐字稿、录音转写（必填）
- 简历：docx/pdf（强烈建议，事实口径以简历为准；无简历时标注"简历未提供，以面试记录为准"）
- 公司/岗位公开信息：按需联网核实（产品名、校招机制等），不得编造

### 2. 读取材料
- 飞书文档：先读 `lark-doc` skill，用 `lark-cli docs +fetch` 读全文（markdown）
- 简历 docx：`textutil -convert txt -stdout`（macOS）或 python-docx；简历 pdf：Read 按页读
- 提取每份材料独有的、不可替代的事实：教育背景、实习经历、项目指标、责任边界

### 3. 事实口径核对（最重要的步骤）
建立"事实与口径账本"，每项写清：【简历事实】【现场表述】【风险】【下次统一口径】。
高频风险：PoC 说成上线、团队指标说成个人结果、指标数字漂移（如 84.7% vs 87%）、责任边界扩大（"搭建操作系统"≠个人全栈落地）。

### 4. 分析与评分
- 判断面试性质：集中面 / 业务面 / 深挖面 / HR 面，决定能力基线
- 提炼：核心判断（一句）、正向信号（3-5 条）、主要失分点（5-6 条）
- 六维综合评价（0-5）：项目真实性 / 产品基本功 / 结构化思考 / 数据意识 / 沟通表达 / 岗位匹配，每维附一句说明
- 面试官能力模型：从提问反推面试官验证的能力维度、验证方式、本轮表现
- 逐题复盘：每题给【考察意图】【回答摘要】【评分】【有效之处】【问题】【优化版回答】

### 5. 生成飞书复盘文档
- 先读 `lark-doc` skill 的 create 工作流，按"分析报告与决策支持"体裁执行
- 章节结构：见 `references/framework.md`
- 可视化：3 个 html5-block（总评 / 流程 timeline / 案例题对比），设计规范见 `references/visualization.md`
- 交付载体默认飞书在线文档；用户点名 Word 时改走 `word` skill

### 6. 验证与交付
- `lark-cli docs +script parse` 校验 XML 通过后创建
- 创建后 fetch 回查：章节结构、3 个可视化、表格、参考来源是否落位
- `present_files` 交付，最终回复 ≤300 字 / ≤8 行

## 硬性原则
1. 区分三层：现场说的 / 简历可证的 / 复盘建议，不得混淆
2. 不把 PoC 写成正式上线，不把团队指标升级为个人结果
3. 数字必须绑定指标名：如 84.7% 采纳率 ≠ 87.6% 人机一致率
4. 逐字稿无明确结论时，不做"是否通过"的推断，注明证据边界
5. 每题复盘必须给出可背诵的优化版回答（用户可直接用于下一场）
6. 可视化承载结论，文字做解释，禁止纯文字堆砌
