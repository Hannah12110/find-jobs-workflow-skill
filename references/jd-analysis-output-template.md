# JD Analysis Output Template

## Purpose

Use this reference when analyzing a job description and deciding how the user's background should be mapped to it.

JD analysis is not only a resume-rewrite task. It must answer:
- whether the role is worth applying to
- why the user is or is not a strong fit
- which experiences should lead the story
- what gaps matter most
- what should be improved before repeated applications to similar roles

Use this after:
- [background-intake-strategy.md](background-intake-strategy.md)
- [project-layering-rules.md](project-layering-rules.md)

## Required Input

Minimum inputs:
- the JD itself
- the user's existing background profile, even if only version 1
- at least one usable experience or project

Helpful but optional inputs:
- company name
- role name
- location
- timing constraints
- user interest level in this role type
- previously used resume versions for similar roles

If the profile is incomplete, continue with best-effort analysis but clearly treat confidence as limited.

## Fixed Output Sections

### A. Apply Recommendation

Always begin with a clear recommendation:
- high
- medium
- low

Explain:
- why this role is recommended or not
- whether the user should invest time into tailoring
- what the biggest upside or risk is

This section should help answer:
Is this role worth applying to now?

### B. Match Assessment

Summarize:
- strongest match points
- secondary match points
- major risks
- obvious weakness areas

Rules:
- distinguish strong evidence from partial evidence
- distinguish real risk from minor imperfection
- avoid generic positivity without proof

This section should answer:
Why does this role fit, and where does it not?

### C. Recommended Storyline

Identify the main role narrative this JD needs.

Examples:
- product planning and feature design
- user growth and conversion
- platform/content operations
- AI workflow and systems thinking
- experimentation and strategy iteration
- independent product building

Then state:
- what should be foregrounded
- what should be backgrounded
- what the resume should feel like overall

This section should answer:
What story should the tailored resume tell?

### D. Project Ranking

List the recommended experience order for this JD.

For each project or experience, identify:
- whether it should lead
- whether it should support
- whether it should stay out of the main version

If ranking changes from the default background profile, explain why.

Also determine:
- whether a multi-role internship should use a different narrative version
- whether a backup project should rise in importance for this JD

This section should answer:
Which projects should be used, and in what order?

### E. Resume Rewrite Strategy

Explain how the materials should be rewritten for this role.

Include:
- which experience should move earlier
- which keywords should be covered
- which wording should become more product-oriented, growth-oriented, strategy-oriented, or operations-oriented
- which content should be weakened, cut, or reserved for interviews

When useful, explicitly state:
- which internship narrative version to use
- which project should be rewritten from a different angle

This section should answer:
How should the resume be adapted, not just which materials should appear?

### F. Gap Diagnosis

Identify:
- hard gaps
- improvable gaps
- bonus gaps

Also identify the most relevant gap dimensions:
- skill gaps
- experience gaps
- evidence gaps
- metrics gaps
- narrative gaps

Do not overstate every missing item as equally severe.

This section should answer:
What is actually missing, and how serious is it?

For classification and prioritization rules, use:
- [gap-diagnosis-rules.md](gap-diagnosis-rules.md)

### G. Evidence and Metrics Still Needed

List what would make the tailored resume stronger.

Common items include:
- metrics still missing
- screenshots, links, prototypes, demos, or writeups still missing
- process depth that needs clearer evidence
- experiments or iterations that need to be surfaced
- range estimates or directional results that should be clarified

This section should answer:
What should the user add next to make this story more credible?

### H. Suggested Next Actions

Close with clear next steps.

Typical next actions include:
- tailor this JD now
- ask follow-up questions on a weak area
- update the master profile
- create or update an application-tracker entry
- prepare interview materials
- strengthen a specific missing capability before repeatedly targeting similar jobs

This section should answer:
What should happen immediately after this analysis?

### I. Likely Interviewer Questions

After a tailored resume has been generated, add a likely interviewer-question step.

Rules:
- first search the web for company-specific interview style for similar roles
- if company-specific signals are found, shape the question set accordingly
- if they are not found, explicitly fall back to a large-tech-company style
- keep the default scope to a 30 to 45 minute interview
- anchor questions to the tailored resume and JD

This section should answer:
If the user gets screened or interviewed next, what is the most likely question set?

## Gap Severity Rules

### Hard Gap
Use when:
- the JD explicitly requires something central
- the user has little or no real evidence for it
- the absence will likely weaken competitiveness significantly

Examples:
- SQL for a strategy/growth role
- strong experimentation evidence for an A/B-testing-heavy role
- overseas operations experience for a clearly overseas-ops role

### Improveable Gap
Use when:
- the user has partial evidence
- the capability exists but is weakly proven
- the material is present but the expression is shallow, generic, or under-quantified

Examples:
- growth work exists, but funnel logic is under-explained
- AI workflow experience exists, but the product-thinking framing is weak
- a project has impact but lacks quantified outcomes

### Bonus Gap
Use when:
- the JD lists something as a plus rather than a core requirement
- the user does not have it
- the absence should not block application
- adding it would still increase competitiveness

Examples:
- prestigious competition awards
- CS background in a role where it is only preferred
- exposure to a specific industry niche

## JD-Specific Ranking Rules

When ranking projects for a JD:
- start from the layered profile
- re-rank by evidence strength and JD relevance
- allow backup high-potential projects to rise
- use supporting experiences only when they strengthen trust
- avoid overcrowding the main narrative

Do not assume one fixed project order across all roles.

Project order should shift when the JD shifts.

## Output Style Rules

- Lead with judgment, then support it.
- Be explicit about evidence versus inference.
- Prefer concise, structured sections over loose commentary.
- Do not jump straight into a full rewritten resume unless the user asks to continue.
- In the analysis stage, prioritize decision support and rewrite strategy.
- If the user continues, then move into resume drafting.

## Common Mistakes

- treating JD analysis as only copy editing
- failing to judge whether the role is worth applying to
- keeping project order static across roles
- ignoring a hard gap because other areas are strong
- overstating a bonus gap as if it were fatal
- missing evidence gaps while focusing only on skill labels
- recommending too many projects in the main story
- not switching narrative versions for multi-role internships

## Exit Criteria

A JD analysis is complete when it has produced:
- a recommendation level
- a match assessment
- a recommended storyline
- a project ranking
- a rewrite strategy
- a gap diagnosis
- an evidence/metrics-needed list
- clear next steps

At that point, the workflow can move into:
- tailored resume drafting
- tracker update
- deeper follow-up questioning
- interview preparation
