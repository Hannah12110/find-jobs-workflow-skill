# Master Profile Template

## Purpose

Use this reference to create or update the user's reusable master profile.

The master profile is the long-lived source of truth behind JD analysis, resume tailoring, application tracking, and interview preparation. It should be more complete than any single resume version and should preserve useful materials even when they are not currently in use.

Core principle:

The master profile should optimize for retrieval and reuse, not for polished one-page presentation.

## Structure

The master profile should usually contain these sections:
- basic identity and availability
- education background
- role interests and constraints
- internships and work experience
- project pool
- skills and tools
- evidence assets
- highlight bank
- narrative preferences and boundaries
- open questions and missing evidence

## 1. Basic Identity and Availability

Capture:
- name
- current school / current stage
- graduation date
- contact information
- portfolio link
- location or relocation preference if relevant
- internship availability

Keep this section concise and factual.

## 2. Education Background

For each school, capture:
- school name
- degree
- major
- date range

Optional:
- honors
- scholarships
- major competitions
- exchange or research experience

Keep awards and competition records separate from the degree rows so they can be shortened or expanded later.

## 3. Role Interests and Constraints

Capture only what is stable enough to matter:
- current role interests
- strong preferences
- strong exclusions if the user explicitly states them
- city / onsite / hybrid constraints
- timing constraints

Do not force narrow target-role definitions too early.

## 4. Internships and Work Experience

For each internship or work experience, store:
- company
- product or business context
- date range
- base facts
- role title used on resumes
- possible narrative versions if responsibilities were split
- relevant projects
- tools used
- key actions
- measurable outcomes
- reflection / iteration notes

If the experience includes multiple tracks, store:
- base facts once
- multiple narrative versions underneath

Example narrative version labels:
- product assistant
- growth / strategy
- KOL operations
- overseas operations

## 5. Project Pool

Store projects in layered form:
- core projects
- backup high-potential projects
- exploratory projects
- supporting experiences

For each project, capture:
- project name
- type
- date
- context / background problem
- user role
- tools
- key actions
- outcomes
- evidence assets
- suitable JD types
- confidence or usage note

If a project is unfinished, still capture:
- intended user problem
- what was attempted
- what blocked it
- what was learned

Do not remove exploratory material just because it is not resume-ready.

## 6. Skills and Tools

Store skills as evidence-backed capabilities where possible.

Recommended categories:
- product capabilities
- data / experiment capabilities
- AI application capabilities
- operations / growth capabilities
- tools
- language ability

For each skill cluster, prefer:
- what the user can do
- which project or experience proves it

Avoid using the master profile as a pure keyword dump.

## 7. Evidence Assets

Track reusable proof materials such as:
- portfolio links
- Figma links
- demo links
- PRD screenshots
- product analysis docs
- project repos
- certificates
- public content
- notable screenshots or artifacts

Each asset should ideally map to one or more projects or experiences.

## 8. Highlight Bank

Store short reusable proof statements that can be pulled into resumes, self-introductions, or interview answers.

Examples:
- strongest product execution proof
- strongest growth proof
- strongest AI workflow proof
- strongest C-end product proof
- strongest language / international context proof

Each highlight should be anchored in real evidence.

## 9. Narrative Preferences and Boundaries

Capture:
- what the user likes to foreground
- what the user does not want overused
- which experiences should be used cautiously
- which items should stay as backup only
- wording boundaries

Examples:
- do not overuse an exploratory MVP
- do not overstate unfinished work
- prefer product framing over creator framing

## 10. Open Questions and Missing Evidence

Maintain a rolling list of unresolved items, such as:
- missing metrics
- unclear dates
- missing links
- unclear ownership
- under-described experiments
- projects that need stronger product wording

This section helps future JD runs become more accurate.

## Recommended Output Shape

A strong master profile should be able to answer:
- who the user is
- what the user has done
- which experiences are strongest
- how those experiences should be layered
- what evidence exists
- what is still missing

It should be stable enough to support many JD runs without rebuilding from scratch each time.

## Writing Guidelines

- prefer reusable structure over polished prose
- keep facts explicit
- separate evidence from interpretation
- preserve weak-but-useful materials
- make multi-role internships easy to reroute
- keep the profile easy to update

## Common Mistakes

- turning the master profile into a one-page resume
- deleting exploratory or unfinished work too early
- storing only polished bullets without background facts
- failing to split multi-role internships
- mixing weak evidence and confirmed evidence without labels
- omitting links and artifacts
- storing skills without proof context

## Exit Criteria

The master profile is good enough for version 1 when it includes:
- identity and education
- at least one strong experience
- a layered project pool
- key skills with rough evidence anchors
- known missing items

Do not wait for perfect completeness before using it.
